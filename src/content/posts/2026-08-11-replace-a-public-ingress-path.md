외부 요청을 받는 구조를 바꾸는 일은 설정 하나를 교체하는 작업처럼 보이기 쉽다. 하지만 기존 프록시 서비스를 다른 구조로 옮기려면 요청이 들어오는 지점만 볼 수 없다. 새 환경에서 내부 서버까지 어떤 경로로 접근할지, 그 경로를 정책상 허용할 수 있는지부터 확인해야 한다.

이번 작업에서는 전체 전환에 앞서 작은 테스트 대상을 먼저 정했다. 새 구조가 동작하는지 살피는 데 필요한 범위는 확보하되, 확인되지 않은 조건이 다른 서비스에 미치는 영향은 제한하려는 선택이었다.

## 문제를 다시 정의하기

처음 보이는 문제는 기존 프록시 서비스를 새 구조로 옮기는 것이었다. 그러나 테스트 대상을 검토하면서 실제 문제는 구조 변경 자체보다 새 인입 경로가 내부 서버까지 안전하게 이어질 수 있는지 확인하는 데 있다는 점이 드러났다.

클라우드의 가상 네트워크에서 사무실 내부 서버로 접근하려면 별도의 네트워크 정책이 필요했다. 따라서 외부 요청을 새 구조가 받아들이는지만 확인해서는 전환 가능 여부를 판단할 수 없었다. 내부 접근 경로와 방화벽 조건까지 검토 범위에 넣어야 했다.

## 선택지를 나눈 기준

판단 기준은 테스트 범위와 선행 조건이었다. 처음부터 넓은 범위를 바꾸면 실제 환경에 가까운 결과를 얻을 수 있지만, 네트워크 정책이 확정되지 않은 상태에서는 어디에서 문제가 생겼는지 구분하기 어렵다.

작은 대상을 먼저 정하면 검증 범위를 좁힐 수 있다. 인입 구조의 문제인지, 내부 접근 정책이나 방화벽의 문제인지 살펴볼 여지도 생긴다. 테스트 대상은 단순히 전환하기 쉬운 서비스를 고르는 문제가 아니라, 아직 확인되지 않은 조건의 영향을 제한하는 장치였다.

## 내린 결정과 실행

첫 시험 대상으로 삼을 서비스를 선정하고 관계자에게 공유했다. 실제 변경에 들어가기 전에 클라우드 환경에서 사무실 내부 서버까지 접근하려면 네트워크 정책이 필요하다는 사실도 확인했다.

여기서 구조 전환을 서두르지 않았다. 안전한 접근 경로와 방화벽 구성을 인프라 담당자가 검토하도록 하고, 그 결과를 다음 판단의 전제 조건으로 두었다. 애플리케이션 설정과 네트워크 변경을 한꺼번에 진행하지 않고, 먼저 통과해야 할 조건을 분리한 셈이다.

## 결과와 남은 문제

현재까지 확정된 것은 테스트 대상과 네트워크 선행 조건이다. 새 구조로 옮길 후보가 구체화됐고, 내부 서버 접근을 위해 추가 검토가 필요하다는 점도 관계자와 공유됐다.

다만 실제 전환이 끝난 것은 아니다. 안전한 접근 경로와 방화벽 구성이 아직 검토 중이므로 새 인입 구조가 운영 환경에서 정상적으로 동작한다고 말할 단계는 아니다. 이번 작업의 결과는 전환 완료가 아니라, 전환 전에 해결해야 할 문제의 경계를 분명히 한 데 있다.

## 다음에 적용할 원칙

외부 인입 구조를 바꿀 때는 먼저 영향이 제한된 테스트 대상을 정한다. 그다음 새 경로가 내부 자원에 닿기 위해 필요한 네트워크 정책과 방화벽 조건을 확인한다.

선행 조건이 남아 있다면 설정 변경을 시작한 사실을 진척으로 보지 않는다. 접근 경로를 검토할 담당자와 판단 기준을 먼저 맞추고, 검토가 끝난 뒤 실제 전환 여부를 결정한다. 작은 테스트는 속도를 늦추는 절차가 아니라, 아직 풀리지 않은 문제를 드러내는 방법이다.
